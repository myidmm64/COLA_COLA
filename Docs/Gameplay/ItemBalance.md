# 단일 효과 아이템 밸런스

> 과거 규칙의 비교 기록이다. 2026-10-19 현재 규칙은 [Items.md](Items.md)를 따른다. 이 문서의 “현재”와 수치·결과는 당시 버전을 뜻하며 새 버전의 검증 결과가 아니다.

이 문서는 이전 조정 당시의 기록이다. 이후 체력·확률·품목 비중·차례당 사용 상한이 변경되었다.
2026-10-18. 효과를 이해하기 쉽게 다시 구성하고 압력과 함께 가상 대전으로 비교했다. 이 문서의 초기 수치 비교는 단일 효과 도입 당시의 기록이다. 이후 경기 길이 조정으로 **현재 체력은 7, 확률 지수는 1.6, 벨은 6토큰/2개**이다. [경기 길이 설계](PacingBalance.md), [현재 전체 효과](Items.md), [최신 요약](../../output/verification/latest/Summary.md)을 따른다.

## 설계

각 아이템은 **효과 하나**, 미래 효과의 기간은 **그 사람이 다음에 흔들 때까지**로 통일한다. 부가 사용료, 특정 확률에서만 나오는 팁, 안전/폭발에 따른 보상 배수 예외를 없앴다. 계산서만 차례를 넘기며 발포 캔디는 압력만 올린다. 번호표는 복잡한 차례 생략 대신 보관 아이템 하나를 취소한다.

피자는 무료로 체력 1만 회복한다. 단일 효과 도입 당시에는 회복 한 번이 경기의 1/3을 되돌리는 문제를 줄이기 위해 기본 체력을 **3 → 4**로 조정했다. 경기 길이 조정 후 현재는 **7**이다. 보스의 단계별 체력 +1과 플레이어의 경기 간 완충은 유지한다. 회복에 새로운 조건을 붙이지 않는다.

압력 후보 +2/+4/+6, +2/+5/+9, +3/+6/+9, +2/+4/+8과 한계 30~40, 확률 지수 1.25도 비교했다. 단일 효과 도입 당시 선택값은 **+2/+4/+8, 한계 25~35, 지수 1(선형)**이었다. 이후 너무 빠른 종료를 줄이기 위해 현재 지수를 **1.6**으로 바꿨다. 한계 30의 새 병에서 현재 위험은 약 1.3%/4.0%/12.1%다. 과거 선형 결과를 현재 결과로 해석하지 않는다.

마개는 확률 대신 피해를 1 줄인다. 폭발 확률이 100%여도 피해를 줄이므로 별도 한계 예외가 없다. 핫소스도 같은 기간의 피해 +1이라 두 효과를 더하고 피해를 0 이상으로 제한하면 된다. 시럽 +3과 매운맛 ×2는 `(기본 압력 + 시럽) × 배수`로 계산한다. 강도를 강제로 고정하지 않는다.

스탬프는 다음 보상 +4, 팁은 즉시 +3이다. 배수·확률 조건이 없다. 한 묶음에는 같은 품목이 두 번 들어가지 않으므로 즉시 잔액을 만드는 아이템은 팁 한 개, 최대 3토큰이다. 현재 6토큰짜리 새 묶음을 아이템만 즉시 사용해 계속 재구매하는 구조는 아니다. 실제 흔들기와 체력의 장기적인 경제는 별도 가상 대전으로 비교한다.

## 모델

`Tools/Balance/simulate_items.py`에 현재 규칙의 `SimpleDuel`과 변경 직전 규칙을 고정한 `LegacyDuel`을 함께 둔다. 과거 모델은 비교 기준이며 현재 Unity 효과로 쓰지 않는다. 현재 수치는 C# 밸런스 상수와 압력 설정을 읽는다.

- 시작 무작위 2개, 보유 8칸, 현재 6토큰/무작위 2개, 기본 안전 1/2/3·폭발 5토큰을 반영한다.
- 압력·예측·폭발·효과 동시 소모·차례 넘김·아이템 취소·회복·보상을 모델링한다. 다음 흔들기 효과는 다른 인물이 터지거나 병이 바뀌어도 보존한다.
- 기대 보상과 체력을 함께 보는 판단형, 항상 강도 1, 항상 강도 3, 무작위 전략을 비교한다. 보스는 공개 상태만 보고 아이템을 선택하고 강도는 현재 구현처럼 무작위다.
- 미러 비교는 양쪽 2개/턴으로 맞춘다. 보스 비교는 플레이어 상한 32개/턴, 보스 2개/턴이며 구매는 판단 시점에 한다.
- 시작품 비교는 관심 품목 1개와 무작위 1개를 주고 선공·후공을 절반씩 바꾼다. 서로 다른 전략은 자리도 바꿔 대전한다.
- 50토큰 스트레스, 체력 차이가 3인 보스, 플레이어 잔액·미사용품을 이어가는 최대 8연속 보스전을 포함한다. 500차례를 넘으면 무승부로 집계한다.
- 한계·아이템·폭발·판단 난수는 분리하고 미래 판정은 읽지 않는다. 최종 비교는 후보 선별과 다른 난수 묶음을 쓴다. Q/W/E는 사용하지 않는다.

확률 경계, 압력 덧셈과 배수, 피해 상쇄, 다음 효과의 일괄 소모, 무료 회복, 즉시 팁, 취소표, 재고/잔액 부족 주문과 묶음 내 중복 금지를 모델 조건 검사로 확인한다. 이것은 **Python 모델의 검사**이며 C# 실행이나 Play 검사가 아니다.

## 해석의 한계

승률은 지정된 휴리스틱끼리의 결과다. 실제 사람의 승률이나 최적 전략을 보증하지 않는다. 이전/새 효과에 맞는 판단을 각각 사용하므로 효과 변경만의 엄밀한 인과 추정도 아니다. 아이템의 가치를 모든 상황에서 같게 만들기보다 특정 시작품의 독주와 한 가지 강도만 고르는 이득을 줄이는 것을 목표로 한다.

Python과 C#의 난수 시퀀스는 다르다. 클릭·모델·Game 뷰·애니메이션·소리는 확인하지 않았다. 모든 조합과 무한 난이도의 균형을 증명하지 않았으며, 후반 연속 보스전은 도달 표본이 적을 수 있다.

## 재실행

사용자가 요청할 때만 실행한다. 가상 대전 요청에는 Unity를 켜거나 Play로 들어가지 않는다. 현재 수치의 재실행 명령은 [공급 방식 설계](ItemSupplyBalance.md)를 따른다. 아래 명령은 초기 단일 효과 비교의 기록이며 당시 고정 프로필과 결과를 설명한다.

```text
python -B Tools/Balance/simulate_items.py --phase screen --games 4000 --profiles old,wide_hp3,double_hp3,double_hp3_ice4,double_hp3_attack,double_hp4
python -B Tools/Balance/simulate_items.py --phase final --profile runtime --games 10000 --seed 7300000
python -B Tools/Balance/simulate_items.py --phase strategies --profile runtime --games 5000 --seed 9200000
python -B Tools/Balance/simulate_items.py --phase contracts --profile runtime
python -B Tools/Balance/simulate_items.py --phase report
```

`output/verification/latest/item-balance/`는 초기 단일 효과 비교 자료다. 현재 경기 길이 비교는 `pacing-balance/`에 보관하고 `Summary.md`, `status.json`, `verification.log`는 최신 결과로 갱신한다. 프리뷰·미리듣기·임시 빌드·프로젝트 복사본을 만들지 않는다.
