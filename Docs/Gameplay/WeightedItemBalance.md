# 콜라 전체 핫소스와 가중 지급

이 문서는 체력 10으로 진행한 이전 가상 비교 기록이다. 이후 사용자 요청으로 현재 시작 체력은 **6**이며, 새 BGM·환경음을 적용했다. 이 변경에 대한 재가상 매치·Play·청취 검사는 실행하지 않았다.
2026-10-18. 피해 증가 효과를 핫소스 하나로 정리하고, 팁 봉투를 삭제했다. 경기를 늘리는 품목의 지급 비중을 낮춘 뒤, 기존 한 보스당 5~8분 목표로 가상 매치를 비교했다.

## 적용 규칙

- 핫소스: **현재 콜라가 교체될 때까지 양쪽 폭발 피해 +1**. 기본 피해 2, 안전 마개가 있으면 1이다. 중첩하지 않으며 중복 사용 시 아이템을 소비하지 않는다.
- 안전한 흔들기·계산서·상대 행동으로 핫소스가 사라지지 않는다. 새 콜라·새 경기·전체 재시작에서 초기화한다. 사용한 사람도 위험을 부담한다.
- 팁 봉투는 시작품·벨·E 메뉴·사용 효과에서 제거했다. 모델 OBJ·메타데이터와 제작 함수도 삭제했다. 옛 Editor 진단 소스가 참조하는 숫자 ID 10만 폐기된 ID로 예약하며 카탈로그·지급 API는 거절한다.
- 시작품과 벨 주문은 같은 가중치를 사용한다. 한 묶음 안에서는 중복 없이, 기존 보유품과는 겹칠 수 있다. 보스도 동일하다.
- **플레이어와 첫 보스 체력 10**. 벨 6토큰/2개, 시작품 2개, 보유 8칸, 압력 +2/+4/+8, 한계 25~35, 확률 지수 1.6을 유지한다. 콜라 교체 시 무료 추가 지급은 없다.

## 확률

첫 추첨 비중 합은 100이다. 얼음컵 8, 발포 캔디 17, 탄산 시럽 15, 취소 번호표 12, 계산서 8, 매운맛 주문서 14, 안전 마개 5, 피자 3, 핫소스 12, 스탬프 6이다. 회복·피해 방어뿐 아니라 압력 완화·차례 넘김·추가 토큰 수입도 장기전에 영향을 주므로 낮은 비중으로 두었다.

두 번째는 이미 뽑은 품목을 제외한 가중치로 다시 뽑는다. 품목 i의 비중이 w_i, 합이 W이면 2개 묶음의 포함 확률은 `w_i/W + Σ(j≠i) (w_j/W) × (w_i/(W−w_j))`다. 예를 들어 피자는 첫 추첨 3%, 2개 묶음에 한 번 포함될 확률 약 6.32%다. [현재 목록](Items.md)과 [최신 확률표](../../output/verification/latest/Summary.md)를 따른다. E는 확률을 적용하지 않는 무료 테스트 메뉴다.

## 가상 매치 결과

후보 9개를 총 **25,200경기**, 별도 난수의 최종 비교를 **40,672경기** 계산했다. 확률 모델·핫소스 유지와 초기화·피해 상쇄·주문 실패의 원자성·가중 묶음의 중복/삭제 품목 배제를 포함한 Python 모델 조건 20,380개가 통과했다. 최종 500차례 제한 무승부는 0회였다.

동일한 새 효과에 체력 7을 유지한 후보는 중앙값 약 4.4분으로 짧았다. 체력 8/9/10과 회복 비중을 달리 비교해, 회복을 드물게 주면서 기본 체력 10으로 버티는 안을 택했다. 상대적으로 회복 비중을 높인 체력 9 후보도 일반 중앙값은 비슷했지만 50토큰 스트레스의 긴 경기 쪽이 더 길었다.

최종 판단형 대 현재 보스 모형에서 중앙값 **6.98분 → 6.49분**, 10분 초과 **12.70% → 1.03%**였다. 수정안의 10~90백분위는 4.84~8.27분이다. 양쪽 50토큰 스트레스의 90백분위는 15.24분에서 9.32분으로 줄었다. 시간은 기존 클립·코드의 연출 길이에 자기 차례당 평균 5초 판단을 더한 추정이며 실제 Play 시간을 측정한 값이 아니다.

지정 시작품은 품목당 1,000경기, 선후공 절반씩 비교했다. 피자 55.4%, 스탬프 53.3%로 이점이 남아 있어 지급 비중을 낮췄다. 다른 품목은 약 49.5~51.8%였다. 이는 지정 휴리스틱의 결과이며 모든 상황에서 같은 가치라는 의미가 아니다.

판단형 미러의 강도 비율은 1/2/3이 약 29%/26%/45%다. 보수적 강도 1 전략은 강도 3 위주보다 강했고, 경기 중앙값도 약 8.2분으로 더 길었다. 판단형은 최적 전략이 아니며 모든 사람의 승률이나 모든 경기의 5~8분을 보증하지 않는다. 최대 8단계 캠페인도 포함하지만 후반 표본은 적다.

## 구현과 재실행

`ColaItemCatalog.DropWeight / DrawRandom`이 카탈로그 순서로 정수 가중치를 누적하고 뽑은 항목을 풀에서 제거한다. `ColaItemController`가 시작품과 주문에 이를 공유하며, 핫소스는 플레이어별 다음 흔들기 플래그가 아닌 콜라 공용 플래그다. `PreviewAction`이 양쪽 피해에 반영하고 `CaptureAction`은 이를 지우지 않는다. `OnBottleReplaced`와 `ResetEffects`에서 해제한다. 보스 AI도 핫소스 사용 시 양쪽 피해가 함께 늘어나는 위험을 계산한다.

수치와 씬 직렬화 체력은 함께 갱신했다. Unity Play·컴파일·실제 Game 뷰·소리는 실행하지 않았다. 옛 `ColaItemVerification`·`ColaBossItemVerification`의 팁·한 번짜리 핫소스·선형 확률·기존 아이템 가격 기대값과 과거 결과는 이번 동작의 통과 근거가 아니다.

사용자가 가상 비교를 요청했을 때만 실행한다.

```text
python -B Tools/Balance/simulate_items.py --phase weighted-screen --profile runtime --games 1400 --seed 21000000
python -B Tools/Balance/simulate_items.py --phase weighted-final --profile runtime --games 3000 --seed 23000000
python -B Tools/Balance/simulate_items.py --phase weighted-report
```

최신 자료는 `output/verification/latest/weighted-items/screen.json`, `final.json`과 상위 `Summary.md`, `status.json`, `verification.log`다. 난수는 폭발·한계·품목·판단으로 분리하고 미래 폭발 난수나 Q/W/E를 쓰지 않는다. 실제 보스 모형은 아이템 최대 2개/턴, 플레이어는 32개/턴으로 모델링하며 주문은 판단 경계에서 수행한다. Python과 C#의 난수열은 다르다. 프리뷰·임시 실행 빌드·프로젝트 복사본은 만들지 않았다.
