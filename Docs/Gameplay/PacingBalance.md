# 한 보스당 5~8분을 위한 조정

이 문서는 이전 조정 당시의 기록이다. 현재는 **체력 10·가중 지급·콜라 전체 핫소스·팁 삭제**를 적용하며 [최신 밸런스](WeightedItemBalance.md)를 따른다.
2026-10-18. 사용자가 원하는 첫 보스 한 경기 길이는 **5~8분**이다. 실제 Play를 실행하지 않고 가상 대전으로 경기 길이와 아이템 경제를 함께 비교했다. 이 문서는 벨 12토큰/4개 당시의 기록이다. 이후 [공급 방식 비교](ItemSupplyBalance.md)로 **현재 벨은 6토큰/2개**로 변경했다. 체력·확률·아이템 효과는 유지한다.

## 적용 수치

| 항목 | 이전 | 현재 |
|---|---:|---:|
| 플레이어·첫 보스 최대 체력 | 4 | 7 |
| 폭발 확률 지수 | 1 | 1.6 |
| 벨: 무작위 아이템 4개 | 10토큰 | 12토큰 |

압력은 +2/+4/+8, 공개 한계는 25~35를 유지한다. 시작품은 무작위 2개, 보유 한도는 8개다. 아이템 11종의 단일 효과와 기본 보상, 보스당 최대 체력 +1, 경기 사이 플레이어 회복·잔액·미사용품 이월도 유지한다. 흔들기·폭발·페이드 연출의 길이는 바꾸지 않았다.

초반 폭발로 체력이 빠르게 소모되던 문제를 줄이기 위해 확률은 `min(1, (흔든 뒤 압력 / 한계)^1.6)`으로 바꿨다. 압력비 20%/50%/80%에서 약 7.6%/33.0%/70.0%이며, 한계에 닿으면 100%다. 체력을 늘리면서 생기는 추가 토큰과 회복·방어의 반복 공급은 벨 가격 12로 조절했다. 가격·묶음 수·빈 칸 설명과 보스 토큰 판단도 공용 상수를 사용한다.

기본값은 `ColaItemBalance.StartingHealth`, MainScene의 양쪽 체력, `PressureInteractionSettings.asset`, 압력 모델·설정 누락 시 기본 지수에 반영했다. 벨 비용은 `ColaItemController.WaiterCost`를 따른다.

## 비교 결과와 시간 가정

최종 비교는 후보 선별과 다른 난수로 **125,794경기**를 계산했다. 500차례 제한 무승부는 0회다. 모델 조건 검사 1,562개도 현재 수치에 맞춰 통과했다. Python 규칙 모델의 결과이며 C#이나 Unity 실행 결과가 아니다.

판단형 플레이어 대 현재 보스 모형에서, 내 차례마다 아이템·강도를 평균 5초 판단한다고 가정하면 중앙값은 **2.99분 → 6.71분**, 3분 미만 종료는 **50.45% → 1.30%**다. 수정안의 10~90백분위는 4.41~9.92분이고 10분 초과는 9.43%다. 모든 경기를 목표 범위에 고정하지 않는다.

시간 계산은 실제 파일에 정의된 흔들기 4.4초, 폭발 시 추가 약 0.99초, 보스 대기 0.65초, 보스 아이템당 0.65초, 주문당 0.8초에 플레이어 판단 시간을 더한다. 실행 시간을 측정한 값이 아니다. 판단 0/3/5/8초일 때 중앙값은 각각 4.48/5.82/6.71/8.05분이다.

같은 5초 가정에서 강도 3 위주 중앙값은 6.26분, 무작위는 7.56분, 강도 1 위주는 9.29분이다. 판단형 미러의 강도 선택은 1/2/3이 약 23%/27%/51%다. 지정된 휴리스틱의 결과로, 사람의 승률이나 최적 전략을 보증하지 않는다.

시작품은 품목당 2,000경기를 선공/후공 절반씩 비교했다. 피자가 53.05%로 가장 높았고 나머지는 약 49~51%였다. 효과를 복잡하게 만드는 추가 제약은 넣지 않았다. 양쪽 50토큰 스트레스에서는 90백분위 약 14분까지 길어져, 자산이 쌓인 상황과 후반 연속 보스전이 첫 경기보다 길어질 가능성은 남는다. 최대 8단계 연속 대전도 비교했지만 뒤 단계는 도달 표본이 작다.

## 재실행과 확인 범위

사용자가 가상 비교를 요청했을 때만 실행한다.

```text
python -B Tools/Balance/simulate_items.py --phase pacing-screen --profile current --profiles current,hp6_curve16_cost12,hp6_curve18_cost12,hp7_curve16_cost12 --games 1600
python -B Tools/Balance/simulate_items.py --phase pacing-final --profile runtime --games 4000 --seed 14000000
python -B Tools/Balance/simulate_items.py --phase pacing-contracts --profile runtime
python -B Tools/Balance/simulate_items.py --phase pacing-report
```

이전 수치는 `PACING_BEFORE`에 고정하고, 최종 현재 수치는 런타임 소스에서 읽는다. 폭발·품목·한계·판단 난수는 분리하며 미래 폭발 난수를 보지 않는다. Q/W/E는 사용하지 않는다. Unity와 Python의 난수 시퀀스는 다르다.

최신 자료는 [결과 요약](../../output/verification/latest/Summary.md)과 `output/verification/latest/pacing-balance/`의 선별·최종·모델 조건 JSON이다. `item-balance/`는 이전 단일 효과 설계 비교 자료다. 이번 변경의 Unity Play·컴파일·실제 Game 뷰·소리·사람의 체감은 확인하지 않았다. 프리뷰·임시 빌드·프로젝트 복사본은 만들지 않았다.
