# 아이템 공급: 작은 벨 주문

> 과거 규칙의 비교 기록이다. 2026-10-19 현재 규칙은 [Items.md](Items.md)를 따른다. 이 문서의 “현재”와 수치·결과는 당시 버전을 뜻하며 새 버전의 검증 결과가 아니다.

이 문서는 이전 조정 당시의 기록이다. 이후 체력·확률·품목 비중·차례당 사용 상한이 변경되었다.
2026-10-18. 사용자가 제안한 콜라마다 무료 지급과 소량 벨 주문을, 기존 5~8분 경기 목표에 맞춰 가상 비교했다. **벨 6토큰으로 랜덤 아이템 2개**를 받는 방식을 적용했다. 콜라 교체 때 무료로 추가 지급하지 않는다.

## 현재 규칙

- 플레이어와 보스 모두 6토큰·빈 칸 2개로 주문한다. 두 조건 중 하나라도 부족하면 결제·추첨·지급하지 않는다.
- 한 주문의 2개 품목은 중복되지 않지만 기존 보유품과는 겹칠 수 있다.
- 경기 중 플레이어는 기존처럼 원하는 때 주문할 수 있다. 보스는 자기 준비 구간에 한 번까지 주문하며 아이템 최대 2개를 사용한다.
- 무작위 시작품 2개, 보유 8칸, 체력 7, 압력 +2/+4/+8, 공개 한계 25~35, 확률 지수 1.6, 아이템 단일 효과는 유지한다.

개당 평균 가격은 기존 12토큰/4개와 동일한 3토큰이다. 첫 주문에 필요한 토큰과 빈 칸을 절반으로 줄여, 작은 보충 주문을 더 일찍 할 수 있게 했다. 벨 호버 설명·부족 조건·주문 결과 메시지·보스 토큰 판단은 공용 비용과 지급 개수를 따른다.

## 선택 근거

선별은 후보별 판단형 1,600경기, 강도 3 위주 800경기, 양쪽 50토큰 스트레스 800경기씩 총 16,000경기다. 무료 지급 후보는 기존 시작품 2개를 유지하고 **이후 병 교체마다 양쪽에 1개씩**, 빈 칸만큼 지급하며 가득 찼으면 보관하거나 나중에 지급하지 않는 규칙으로 비교했다.

자기 차례당 평균 5초 판단을 가정한 중앙값은 기존 벨 약 6.7분, 무료 1개 추가 약 9.0분, 벨 6토큰/2개 약 7.0분, 벨 5토큰/2개 약 7.6분, 무료 1개와 소량 벨을 함께 적용하면 약 8.7분이었다. 무료 지급과 추가 할인은 회복·방어·보상 품목의 총 공급을 늘려 긴 경기 비율을 높였다.

다른 난수의 최종 20,648경기에서는 판단형 대 현재 보스 모형 중앙값이 6.77분에서 **6.99분**으로 바뀌었다. 모든 경기를 5~8분으로 보장하는 수치는 아니다. 모델 조건 검사 1,562개가 통과했고 500차례 제한 무승부는 0회였다. 상세 전략·스트레스·캠페인은 [최신 요약](../../output/verification/latest/Summary.md)과 `output/verification/latest/item-supply/`의 `screen.json`, `final.json`을 따른다.

## 범위와 재실행

Python 규칙 모델의 결과다. Unity Play·컴파일·화면·소리는 실행하지 않았다. 시간은 기존 클립·코드에 정의된 연출 시간에 판단 시간을 더한 추정치이며 실제 사람의 시간을 측정하지 않았다. 전략은 공개 상태를 보는 휴리스틱이고 미래 폭발 난수나 Q/W/E를 쓰지 않는다. 구매는 판단 경계에서 수행한다. 실제 사람의 아이템 보관·연속 사용·주문 시점에 따라 결과는 달라진다. 50토큰 스트레스와 최대 8단계 캠페인을 포함하지만 뒤 단계는 표본이 적고 무한 난이도를 보증하지 않는다.

사용자가 가상 비교를 요청했을 때만 실행한다.

```text
python -B Tools/Balance/simulate_items.py --phase supply-screen --profile runtime --games 1600 --seed 18000000
python -B Tools/Balance/simulate_items.py --phase supply-final --profile runtime --games 2000 --seed 19000000
python -B Tools/Balance/simulate_items.py --phase supply-report
```

`Profile.order_pack`과 `bottle_items`로 후보를 구분한다. 실제 적용값은 `ColaItemController.WaiterCost / WaiterItemCount`에서 읽고, 현재 무료 지급은 0으로 모델링한다. 구매 모델 조건은 지급 개수에 맞춘 잔액·빈 칸·중복 금지·실패 시 난수 불변을 확인한다. 이전 `pacing-balance/`, `item-balance/`는 해당 조정 당시의 비교 기록이며 현재 공급 수치의 결과로 해석하지 않는다.
