# 플레이 가능한 기본 대전

`Assets/Scenes/MainScene.unity`에서 Play를 누르면 보스와 1대1 경기가 시작된다. 자동 손 미리보기와 기존 임시 소품·보조광은 숨기고, 아이템은 양쪽 8칸 트레이에 실제 모델로 표시한다.

## 조작

- 테이블의 1·2·3 버튼 또는 숫자키로 흔들기 강도를 선택한다.
- 중앙 콜라 클릭 또는 Space로 확정한다. 선택 전에는 확정되지 않는다.
- 다음 조작을 알리는 호버 아웃라인: 마우스를 올린 1·2·3 버튼의 `BeveledKeycap` 본체를 표시하며, 강도 선택 후 다른 버튼으로 변경할 때도 같은 호버를 유지한다. 강도 선택 후에는 콜라에 마우스를 올릴 때 몸통·뚜껑·라벨을 합친 바깥 윤곽을 표시한다. 마우스를 떼면 즉시 숨긴다. 클릭과 같은 첫 충돌 Raycast를 사용해 다른 소품이나 주문서 뒤의 대상은 강조하지 않는다. 3D 숫자는 제외 마스크만 사용하고 색 선은 그리지 않으며, 라벨 글자와 내부 경계도 표시하지 않는다. SkinnedMeshRenderer와 블렌드 셰이프를 지원한다. 주문서 집기/내려놓기 중, 흔들기·폭발·페이드·보스 턴·승패 확정 시에는 숨긴다. 명도를 조금 낮춘 황금색이며 버튼과 콜라 모두 2.5픽셀이다. `ColaInteractionGuide`가 Play 시작 시 자동 연결한다. 이 변경은 사용자 직접 확인 대상으로, 에이전트 검증을 실행하지 않았다.
- 자신의 손 동작 이후 보스가 자동으로 행동하며, 보스가 끝나면 다시 선택한다.
- 이전 메뉴판 자리의 **웨이터벨**을 클릭하면 **6토큰으로 무작위 아이템 2개**를 받는다. 경기 중에는 보스 턴·흔들기·복귀 연출 중에도 쓸 수 있고 콜라당 제한은 없다. 빈 칸이 2개 미만이거나 잔액이 부족하면 결제하지 않는다. 한 묶음 안에서는 중복 없이 뽑으며 시작부터 보유한 품목과는 겹칠 수 있다. 일반 메뉴판은 제거했고 E 무료 테스트 도구로만 남긴다. 디버그는 Q 토큰 999, W 폭발 100%, E 무료 메뉴이며 좌측 상단에 안내한다. 아이템은 청록색 플레이어 트레이와 붉은 보스 배송 상자에 놓이며 소유자 글자는 사용하지 않는다. 효과·보유·테스트 조작은 [Items.md](Items.md)를 따른다.
- 보스도 자기 토큰 6개로 무작위 아이템 2개를 주문하고 자기 턴에 사용한다. 보스 트레이의 실제 아이템 모델과 양쪽 대기 효과로 확인할 수 있다. 취소 번호표는 상대의 보관 아이템 하나를 무작위로 제거한다.
- R은 경기 도중에도 전체 진행을 초기화한다.
- 승리 시 NEXT LEVEL 버튼 또는 Enter로 다음 난이도에 도전한다. 패배 시 RESTART RUN 또는 Enter로 처음부터 재시작한다. 새 경기 상태는 검은 화면에서 정리하고 0.38초 페이드인 뒤 조작을 연다.

## 임시 경기 규칙

- 플레이어와 첫 보스의 체력은 각각 6이다. 자기 차례에 폭발하면 기본 피해 1을 받고 마개·핫소스의 보정을 적용한다.
- 체력이 0이면 즉시 승패를 확정하고 추가 행동을 막는다. 플레이어가 패배한 뒤 보스가 추가로 흔들지 않는다.
- 보스를 격파할 때마다 같은 보스의 최대 체력이 1 증가한다. 최대 99이며, 다음 대전 시작 시 플레이어 체력은 전부 회복한다.
- 안전한 행동은 강도만큼 1·2·3토큰, 폭발한 행동은 강도와 관계없이 **총 5토큰**을 받는다. 스탬프는 다음 흔들기 보상에 +4토큰이다. 피자는 추가 비용 없이 체력 1을 회복한다. 양쪽 단말기에 체력과 토큰을 실제 상태로 표시한다.
- 양쪽은 현재 10종에서 각각 가중 무작위로 뽑은 아이템 2개를 가지고 시작하며 한 사람의 시작품은 중복되지 않는다. 플레이어 토큰과 미사용 아이템은 다음 난이도에 이어지고, 새 보스는 토큰 0·무작위 시작 아이템 2개부터다. 대기 효과는 다음 난이도에서 초기화한다. 전체 재시작은 난이도 1·토큰 0·양쪽 무작위 2개로 되돌린다. 토큰 상한은 9,999개다.
- 새 병의 공개 한계는 **25~35**다. 기본 폭발 확률은 `min(1, (흔든 뒤 압력 / 한계)^1.6)`이며 한계 도달 시 100%다. 양쪽 모두 버튼 1/2/3의 기본 압력 증가량은 **2/4/8**이다. 한계 30·현재 압력 6에서는 강도 1/2/3이 약 12.1%/17.2%/29.5%다. 보스는 임시로 강도 1~3을 무작위 선택하며 아이템으로 그 위험에 대응한다. 매운맛 주문서는 상대의 다음 압력 증가량을 2배로 만든다. 시럽의 +3을 먼저 더한 뒤 배수를 적용한다. 가상 대전은 진행했으며 Unity Play 검사는 실행하지 않았다.
- 아이템으로 압력·차례·보관품·피해·보상을 변경할 수 있다. 기본 폭발 피해는 1이며 핫소스는 현재 콜라가 교체될 때까지 양쪽 폭발 피해를 +1, 마개는 자신의 다음 흔들기 피해를 -1로 만든다. 피해는 최소 0이다. 다음 흔들기 효과는 안전 여부와 관계없이 해당 행동에서 함께 소모하지만, 핫소스는 안전한 행동이나 차례 넘김 뒤에도 유지하며 병 교체 때 해제한다. 핫소스는 중첩되지 않는다. 폭발은 원본 손으로 병을 잡고 흔드는 도중 약 0.24초의 압력 고조 뒤 발생한다. 뚜껑·탄산·거품·손 반동·카메라 충격·파열음이 재생되고 손 동작이 끝난 뒤 새 병으로 교체한다. 피해와 토큰은 기존 결과 콜백에서 한 번만 적용한다. 연출 상세는 `Docs/Art/ColaBurst.md`를 따른다.

## 연결과 검증

`08_Devices/DuelRules`의 `ColaDuelController`가 경기 상태와 보상을 관리한다. 기존 `ShakeSelectionInteraction`은 압력·교대 행동, `StatusTerminalDisplay`는 실제 3D 단말기 표시를 담당한다. `ColaDuelHUD`는 경기 종료 시 중앙 승패/다음 경기 버튼만 표시한다. 플레이 중 상하 UI 바와 보스 사용 알림 패널은 제거했고 아래에는 **내 효과**, **보스 효과** 두 줄만 남겼다. 아이템을 가리킬 때의 이름·효과 툴팁은 유지한다. 양쪽 인벤토리는 [10종 실제 모델](../Art/ItemModels.md)을 사용한다. 이 UI·모델 변경은 에이전트 검증을 실행하지 않았다.

아웃라인은 원래 키캡/콜라 실루엣을 색 없이 스텐실에 기록한 뒤, 원래 메시를 화면의 상하좌우·대각선 8방향으로 일정 픽셀만큼 옮겨 그린 것 중 마스크 바깥만 남긴다. 각 정점을 중심에서 방사형으로 밀던 방식은 제거해 콜라 바닥의 삼각형이 길게 늘어나 뾰족해지지 않도록 했다. 내부 마스크는 깊이와 무관하게 원래 실루엣 전체를 기록해 앞에 있는 숫자나 불투명 라벨 때문에 빈틈이 생기지 않도록 한다. 버튼 숫자는 색 선 없이 제외 마스크만 추가한다. 콜라는 몸통·뚜껑·라벨 메시를 하나의 마스크 영역으로 합쳐 라벨 표면·글자·안쪽 경계가 노랗게 채워지지 않도록 한다. 색 선 자체는 일반 깊이 검사를 유지해 다른 소품 너머로 비치지 않는다. 원본 재질과 투명도는 바꾸지 않는다. 마스크와 선은 같은 호버 조건으로 켜고 끄며 콜라의 블렌드 셰이프도 함께 따른다. 버튼은 4.5에서 2.5픽셀로 줄였고 콜라는 2.5픽셀을 유지한다. 황금색 명도도 이전에 낮춘 값을 유지한다. 이 수정은 사용자 요청에 따라 검증하지 않았다.

`COLA_COLA > Set Up Playable Duel`은 씬 연결과 체력 기본값을 적용하며 자동으로 Play 검사를 시작하지 않는다. 검증은 사용자가 명시적으로 요청할 때만 진행한다. 기존 `PlayableDuelVerification.Begin`은 이전 규칙 기준으로 실제 Raycast 입력, 손 상태, 보상·피해·승패·재시작을 검사했다. 현재 효과에 맞춘 기대값 갱신이 필요하며 과거 결과를 현재 통과 근거로 사용하지 않는다. 별도 카메라나 프리뷰 캡처를 만들지 않으며 자동 검사 통과를 실제 Game 뷰 시각 확인으로 표현하지 않는다.

현재 시작 체력은 사용자 요청으로 6으로 낮췄다. 지수 1.6·벨 6토큰/2개·단일 효과는 유지하며 콜라 교체 시 무료 추가 지급은 없다. 현재 체력 6의 경기 길이는 다시 가상 비교하거나 측정하지 않았다. 효과·지급 확률은 [WeightedItemBalance.md](WeightedItemBalance.md)를 따르지만 그 문서의 가상 매치 수치는 이전 체력 10 기준이다. [기존 경기 길이 설계](PacingBalance.md)와 [가상 대전 기록](../../output/verification/latest/Summary.md)은 현재 Play 검사의 통과 근거가 아니며 실제 동작·화면·새 BGM과 환경음은 확인하지 않았다.
