# 주문과 채택 아이템

기준: [Notion 채택 아이템 표](https://app.notion.com/p/3faa1bc58c8e8166bc7ed3fb286bf36c). 가격은 표의 11종을 그대로 사용한다.

## 사용 흐름

`MainScene`에서 Play → 시작 아이템을 사용하거나 흔들기로 토큰 획득 → **내 턴에 원하는 때** 테이블 앞쪽 오른편의 주문서 모델 클릭 → **품목 오른쪽 가격 버튼으로 수량 담기** → 필요하면 **- 버튼으로 하나 빼기** → 아래 **ORDER 버튼으로 총수량·총액을 확인하고 한 번에 결제** → 오른쪽 보관함의 **큐브 클릭**으로 사용한다. 주문서의 **아이템 이름 또는 가격**에 마우스를 올리면 아래쪽에 효과가 표시된다. 이름 클릭은 설명만 보여 준다. **X 버튼** 또는 **Esc**는 담은 내역을 취소하며 주문 기회를 소비하지 않는다. 큐브에 마우스를 올려도 이름과 효과가 표시된다. 큐브의 01~11은 아래 품목 번호다.

- 양쪽 모두 **얼음컵 1개 + 안전 마개 1개**, 토큰 0으로 시작한다. 각자 보유 한도 6개. 주문 확정 시 자기 토큰으로 총액을 결제하며 처음 빈 슬롯부터 큐브가 놓인다. 앞줄 3개와 높은 뒷줄 3개의 칸을 둔다. 플레이어는 **청록색 손잡이 서빙 트레이**, 보스는 **붉은 배송 상자·금속 손잡이·피자 문양**으로 구분한다. 보스 보관함은 뒤쪽의 높은 받침 위에 놓이며 BOSS/YOU 소유자 글자는 사용하지 않는다.
- **콜라마다 전체 11종 중 중복 없는 6종을 무작위로 선정**해 메뉴판에 표시한다. 같은 콜라에서는 메뉴를 닫았다 열거나 강도를 바꿔도 6종이 유지된다. 보스도 동일한 6종 안에서 주문하며, 메뉴에 없는 품목은 구매 API로도 살 수 없다. 보유 중인 나머지 아이템은 계속 사용할 수 있다. 메뉴 추첨 난수는 폭발 판정·보스 선택 난수와 분리한다.
- **콜라 한 병당 각자 한 번, 자기 턴에 원하는 때 주문**할 수 있다. 한 번에 여러 종류와 같은 종류의 여러 수량을 담을 수 있으며 보유 한도 6개와 토큰 총액을 넘길 수 없다. **주문 확정 성공 시에만** 해당 병의 기회를 소비한다. 안전하게 흔들기·턴 넘기기·턴 건너뛰기 후에도 주문하지 않았다면 이후 자기 턴에 주문할 수 있다. 보기·담기·취소·결제 실패는 기회를 유지한다. 새 콜라에서 양쪽 기회가 돌아온다.
- 메뉴판은 **실제로 주문 가능한 내 턴에만 표시**한다. 주문 완료·보스 턴·연출 중·승패 확정뿐 아니라 토큰 부족으로 살 수 있는 품목이 없거나 보유 칸이 가득 차도 모델과 입력 콜라이더 전체를 숨긴다. 들고 있던 메뉴판이 숨겨지면 미결제 내역을 취소하고 입력 잠금을 해제한다. 미사용 주문 기회와 토큰·빈 칸 조건이 충족되면 같은 메뉴로 다시 나타난다.
- 플레이어는 흔드는 도중·보스 턴·승패 확정 후에는 주문과 사용을 할 수 없다. 보스는 자기 턴의 준비 구간에서 주문·사용한다. 주문서를 들고 있거나 내려놓는 중에는 게임 조작을 막는다. 화면 상점과 Tab 열기는 제거했고, 실제 3D 종이 위 버튼의 Raycast로만 구매한다.
- 총액 부족·빈 슬롯 부족·메뉴에 없는 품목은 주문 전체를 거절하며 부분 결제나 일부 지급을 하지 않는다. 체력 최대·압력 0·같은 대기 효과 사용 중 등 사용할 수 없는 아이템은 큐브를 보존한다.
- 모두 일회용. 같은 종류의 큐브를 여러 개 살 수 있지만 같은 대기 효과는 중첩되지 않는다. 서로 다른 효과는 함께 사용할 수 있다.
- 다음 보스에서 플레이어 토큰과 미사용 큐브는 유지한다. 새 보스는 토큰 0과 시작 아이템 2개를 받고 양쪽 대기 효과는 초기화한다. R 재시작은 양쪽 토큰 0·시작 아이템 2개·대기 효과 없음으로 되돌린다.

## 보스의 자동 주문·사용

보스도 같은 11종과 가격을 사용한다. **한 병당 한 번의 주문에 최대 3개 구매**하며 잔액과 빈 칸 안에서 유효한 품목을 함께 고른다. 자기 턴마다 **최대 2개 사용**하며 기존 보유품을 먼저 고려한다. 체력이 부족하면 피자를, 위험한 압력에서는 안전 마개·얼음컵·턴 넘기기 품목을 우선 평가한다. 나머지 상황에서는 방해·추가 보상 품목 중 적절한 것을 고른다. 공개된 압력·확률·체력과 보유 토큰으로 판단하고, 비슷한 선택에는 작은 무작위 편차를 준다. 실제 폭발 난수는 읽거나 소모하지 않는다.

체력이 부족하고 피자 가격 8토큰에 못 미치면 예상 위험 35% 미만에서는 구매를 보류해 회복 비용을 모은다. 이미 가진 사용 가능한 아이템은 계속 고려하며, 위험이 높으면 방어·턴 넘기기에 토큰을 쓸 수 있다.

주문 후 큐브를 약 0.8초 보여 주고 사용 후 약 0.65초 기다린다. 사용 알림과 양쪽 대기 효과를 표시한다. 보스의 큐브에 마우스를 올려 정보를 볼 수 있고 플레이어가 대신 사용할 수는 없다.

아래 효과의 ‘자신’과 ‘상대’는 사용 주체에 따른다. 보스의 시럽·매운맛 주문서는 플레이어의 다음 흔들기에, 안전 마개·스탬프·팁은 보스 자신의 다음 흔들기에 적용된다. 보스가 번호표를 쓰면 다음 플레이어 턴을 한 번 건너뛰고 보스가 한 번 더 행동한다. 플레이어가 보스 턴을 건너뛰면 그 턴의 자동 주문도 실행하지 않는다.

## 효과

| 번호 | 이름 | 토큰 | 적용 |
|---|---|---:|---|
| 01 | 얼음컵 | 3 | 압력 -3(최소 0). 현재 선택과 자신의 턴을 유지한다. |
| 02 | 발포 캔디 | 7 | 압력 +4 후 상대 턴. 사용 자체로 흔들기·폭발 판정·보상을 만들지 않는다. |
| 03 | 탄산 시럽 | 4 | 상대의 다음 실제 압력 증가량 +2. 선택 강도와 강도 보상은 그대로다. |
| 04 | 대기 번호표 | 3 | 다음 상대 턴 한 번을 건너뛰고 자신의 턴. 건너뛴 행동의 보상은 0. |
| 05 | 계산서 | 5 | 흔들지 않고 바로 상대 턴. 넘긴 행동의 보상은 0. |
| 06 | 매운맛 주문서 | 3 | 다음 상대의 선택 강도를 3으로 고정. 시럽과 함께 쓰면 압력 +5, 안전 보상 3. |
| 07 | 안전 마개 | 4 | 자신의 다음 흔들기 확률 -30%p(최소 0%). 한계 도달·초과는 항상 100%. |
| 08 | 피자 한 조각 | 8 | 자신의 체력 +1. 최대 체력을 넘지 않는다. |
| 09 | 핫소스 | 3 | 현재 콜라에서 발생할 폭발 피해 1→2. 터뜨린 인물이 피해를 받고 새 콜라에서 해제. |
| 10 | 더블 스탬프 | 4 | 자신의 다음 흔들기 토큰 전체 2배. 폭발 5→10, 팁 보상도 포함. |
| 11 | 팁 봉투 | 1 | 자신의 다음 흔들기가 **최종 확률 50% 이상이며 안전할 때** 토큰 +3. 조건 미달·폭발이어도 그 흔들기에서 효과 소모. |

압력 변경만으로 폭발 판정을 하지 않는다. 예를 들어 캔디로 한계를 넘겨도 다음 상대의 실제 흔들기에서 폭발한다. 개인의 다음 흔들기 효과는 계산서·캔디·상대 행동으로 소모되지 않는다. 번호표로 건너뛴 인물의 시럽·매운맛 주문서도 그 인물이 실제로 흔들 때까지 남는다.

## 구현과 검증

`ColaItemCatalog`에 이름·가격·설명을 모았다. `ColaItemController`는 양쪽 일괄 결제·병당 주문 기회·시작 아이템·슬롯·대기 효과, `ColaItemPresentation`은 런타임 Cube와 모서리를 깎은 보관함 메시·칸막이·손잡이를, `ColaBossItemAI`는 보스의 선택을 담당한다. `ColaOrderSheet`는 클립보드·접힌 종이·금속 클립·입체 가격/수량 빼기/주문 확정 버튼과 집기/내려놓기를 만든다. 종이는 밝은 불투명 Unlit 재질로 방 조명과 관계없이 읽을 수 있게 한다. `ColaWorldText`와 전용 글리프 셰이더는 깊이 검사를 사용해 아이템 번호가 앞의 주문서나 모델을 뚫지 않게 한다. 동적 한글 폰트의 아틀라스 갱신도 따라간다. 화면 Canvas나 GUI 상점은 사용하지 않는다. 기존 장식 아이템과 전용 보조광은 계속 비활성화한다.

`BottlePressureModel`이 예고와 실제 판정에 같은 압력·확률 보정을 사용한다. 선택 강도와 실제 증가량을 구분하므로 시럽이 보상을 늘리지 않는다. 확정 시 효과를 스냅샷으로 보관해 병 교체가 먼저 일어나더라도 해당 폭발의 피해·보상이 보존된다.

검증 실행: `ColaCola.Editor.ColaItemVerification.Begin`. 실제 Unity Play 모드에서 11종, 여섯 큐브의 Raycast 입력, 결제 실패, 중첩 방지, 확률계 연동, 양쪽 원본 손 이동, 턴 제어, 체력·보상·승리·재시작을 확인한다. 이어 기존 `PlayableDuelVerification` 회귀 검사를 실행한다. 최신 결과는 `output/cola-items/Playmode-validation.txt`에 기록한다. 테스트 전용 토큰·체력 조정은 Editor 검증 코드에만 있으며 게임 시작값에는 반영하지 않는다. 자동 상태 검사이며 Game 뷰 시각 확인은 별개다.

보스 통합 검증은 `ColaCola.Editor.ColaBossItemVerification.Begin`으로 실행하고 `output/boss-items/Playmode-validation.txt`에 기록한다. 양쪽 12개 큐브의 화면 범위·가림 Raycast, 보스의 11종 효과와 소유권·계좌 분리, 강도 강제와 플레이어 압력계, 양방향 턴 건너뛰기·넘기기, 자동 구매 중 재시작 및 실제 0토큰 시작의 자력 구매를 검사한다. 이어 플레이어 아이템과 기본 대전 검사를 실행한다. 이 두 회귀 검사는 보스 선택 로직과 분리한 고정 조건을 위해 해당 검증 안에서만 자동 아이템 사용을 끈다.

주문서 검증 진입점은 `ColaCola.Editor.ColaOrderSheetVerification.Begin`이다. Play에서 실제 가격·수량 빼기·주문 확정 버튼의 Raycast, 취소 시 무결제, 같은 병의 이후 턴 주문, 여러 종류·수량의 정확한 일괄 결제, 부족한 총액·빈 칸·잘못된 품목의 부분 결제 차단을 검사한다. 양쪽 새 보관함의 메시·재질·여섯 칸과 12개 큐브의 화면 범위·구조물 가림 Raycast도 확인한다. 32병의 중복 없는 6종 추첨, 재열기 중 메뉴 유지, 보스와 같은 메뉴, 독립된 폭발 난수, 토큰·공간·차례·주문 여부에 따른 숨김과 잠금 해제, 11종 전체 결제, 실제 폭발 후 새 메뉴·주문 기회 및 재고 보존을 검사한다. 이어 보스·플레이어 아이템과 기본 대전의 Play 검사를 실행한다. 최신 결과는 `output/order-sheet/Playmode-validation.txt`와 `unity-playmode.log`부터 기록한다. 복합 효과 검사는 Editor 전용 설정으로 시작 인벤토리를 비우고 이전 병의 재고를 준비하며, 특정 품목이 필요한 시나리오는 실제 새 병 추첨으로 메뉴를 준비한다. 자동 상태 검사는 실제 Game 뷰 시각 검수를 대신하지 않는다. 프리뷰나 연속 캡처는 만들지 않는다.
