# 주문과 채택 아이템

기준: [Notion 채택 아이템 표](https://app.notion.com/p/3faa1bc58c8e8166bc7ed3fb286bf36c). 가격은 표의 11종을 그대로 사용한다.

## 사용 흐름

`MainScene`에서 Play → 시작 아이템을 사용하거나 흔들기로 토큰 획득 → **내 턴에 원하는 때** 테이블 앞쪽 오른편의 주문서 모델 클릭 → **품목 오른쪽 가격 버튼으로 수량 담기** → 필요하면 **- 버튼으로 하나 빼기** → 아래 **주문 버튼으로 총수량·총액을 확인하고 한 번에 결제** → 오른쪽 보관함의 **아이템 모델 클릭**으로 사용한다. 주문서의 **아이템 이름 또는 가격**에 마우스를 올리면 아래쪽에 효과가 표시된다. 이름 클릭은 설명만 보여 준다. **X 버튼** 또는 **Esc**는 담은 내역을 취소하며 주문 기회를 소비하지 않는다. 실제 아이템 모델에 마우스를 올려도 이름과 효과가 표시된다. 큐브와 떠 있는 품목 번호는 제거했다. [11종 모델 구성](../Art/ItemModels.md)을 따른다.

- 양쪽 모두 **얼음컵 1개 + 안전 마개 1개**, 토큰 0으로 시작한다. 각자 보유 한도 6개. 주문 확정 시 자기 토큰으로 총액을 결제하며 처음 빈 슬롯부터 해당 아이템 모델이 놓인다. 앞줄 3개와 높은 뒷줄 3개의 칸을 둔다. 플레이어는 **청록색·아이보리 테두리의 서빙 트레이**, 보스는 **붉은 배송 상자·금속 모서리·피자 문양**으로 구분한다. 양쪽 모두 옆면에 들어간 작은 손잡이 형태를 사용한다. 보스 보관함은 뒤쪽의 높은 받침 위에 놓이며 BOSS/YOU 소유자 글자는 사용하지 않는다.
- **콜라마다 전체 11종 중 중복 없는 6종을 무작위로 선정**해 메뉴판에 표시한다. 같은 콜라에서는 메뉴를 닫았다 열거나 강도를 바꿔도 6종이 유지된다. 보스도 동일한 6종 안에서 주문하며, 메뉴에 없는 품목은 구매 API로도 살 수 없다. 보유 중인 나머지 아이템은 계속 사용할 수 있다. 메뉴 추첨 난수는 폭발 판정·보스 선택 난수와 분리한다.
- **콜라 한 병당 각자 한 번, 자기 턴에 원하는 때 주문**할 수 있다. 한 번에 여러 종류와 같은 종류의 여러 수량을 담을 수 있으며 보유 한도 6개와 토큰 총액을 넘길 수 없다. **주문 확정 성공 시에만** 해당 병의 기회를 소비한다. 안전하게 흔들기·턴 넘기기·턴 건너뛰기 후에도 주문하지 않았다면 이후 자기 턴에 주문할 수 있다. 보기·담기·취소·결제 실패는 기회를 유지한다. 새 콜라에서 양쪽 기회가 돌아온다.
- 메뉴판은 **실제로 주문 가능한 내 턴에만 표시**한다. 주문 완료·보스 턴·연출 중·승패 확정뿐 아니라 토큰 부족으로 살 수 있는 품목이 없거나 보유 칸이 가득 차도 모델과 입력 콜라이더 전체를 숨긴다. 들고 있던 메뉴판이 숨겨지면 미결제 내역을 취소하고 입력 잠금을 해제한다. 미사용 주문 기회와 토큰·빈 칸 조건이 충족되면 같은 메뉴로 다시 나타난다.
- 플레이어는 흔드는 도중·보스 턴·승패 확정 후에는 주문과 사용을 할 수 없다. 보스는 자기 턴의 준비 구간에서 주문·사용한다. 주문서를 들고 있거나 내려놓는 중에는 게임 조작을 막는다. 화면 상점과 Tab 열기는 제거했고, 실제 3D 종이 위 버튼의 Raycast로만 구매한다.
- 총액 부족·빈 슬롯 부족·메뉴에 없는 품목은 주문 전체를 거절하며 부분 결제나 일부 지급을 하지 않는다. 체력 최대·압력 0·같은 대기 효과 사용 중 등 사용할 수 없는 아이템은 큐브를 보존한다.
- 모두 일회용. 같은 종류의 큐브를 여러 개 살 수 있지만 같은 대기 효과는 중첩되지 않는다. 서로 다른 효과는 함께 사용할 수 있다.
- 다음 보스에서 플레이어 토큰과 미사용 큐브는 유지한다. 새 보스는 토큰 0과 시작 아이템 2개를 받고 양쪽 대기 효과는 초기화한다. R 재시작은 양쪽 토큰 0·시작 아이템 2개·대기 효과 없음으로 되돌린다.

## 디버그 구매 옵션

Game 뷰에 포커스를 둔 상태에서 **왼쪽/오른쪽 Ctrl을 한 번 누르면 토큰 무제한과 반복 주문이 함께 켜지고, 다시 누르면 함께 꺼진다.** 누르고 있어도 반복 전환하지 않는다. 기본값은 둘 다 꺼짐이다. 개별 조절이 필요하면 Hierarchy의 `COLA_COLA_MainScene/08_Devices/DuelRules`를 선택하고 `Cola Duel Controller`의 **Debug (Editor / Development Build)** 항목에서 변경할 수 있다.

- **Debug Infinite Tokens**: 플레이어의 구매 비용 조건과 차감을 무시한다. 메뉴판에는 `TOKENS ∞`, 숫자 전용 체력/토큰 단말기에는 `9999`를 표시한다. 실제 잔액은 별도로 그대로 두며 흔들기 보상도 정상 적립한다. 끄면 실제 잔액으로 즉시 돌아온다.
- **Debug Unlimited Orders**: 같은 콜라에서 여러 번 주문할 수 있다. 주문 한 번을 확정하면 메뉴판은 내려놓지만 빈 칸이 있으면 다시 사용할 수 있다. 켜기 전 이미 주문했어도 재주문할 수 있고, 옵션을 끄면 실제 주문 이력에 따라 병당 1회 제한으로 돌아간다.

두 옵션은 독립적이며 플레이어에만 적용한다. 내 턴·연출 중 잠금·보유 한도 6개·해당 콜라의 무작위 6종 메뉴는 유지한다. 가득 찼으면 아이템을 사용해 칸을 비운 뒤 다시 주문한다. 재시작과 다음 보스에서도 켜 둔 옵션을 유지한다. 에디터와 Development Build에서만 동작하고 일반 빌드에서는 비활성이다. 이 변경은 Play·컴파일·자동 검증을 실행하지 않았다.

## 메뉴판 디자인

집어 든 메뉴판은 낡은 동네 피자리아의 종이 메뉴를 기준으로 한다. 크림색 종이에 고정된 픽셀 종이결·접힌 자국·옅은 컵 얼룩을 넣고, 아래쪽의 잘린 가장자리·테이프·닳은 클립보드와 금속 클립을 더했다. 상단은 약간 기울어진 `PIZZERIA`·`MENU` 인쇄와 바랜 붉은 체크 패턴을 쓰며, 토큰·보유 수량 뒤의 카드형 배경은 제거했다. 기본 품목 행은 종이 위 인쇄처럼 두고 **담은 행에만** 배경색을 표시한다. 번호 배지도 살짝 불균일한 도장 형태로 두고 가격·주문 버튼의 두께를 줄였다.

메뉴 번호는 해당 콜라에 표시된 순서대로 **1~6**이며 큐브의 품목 번호와 별개다. 담은 품목은 배경과 가격 버튼 색으로 표시하고, 아래 넓은 **주문** 버튼에서 수량과 총액을 보여 준다. 비어 있을 때는 버튼에 ‘주문’만 표시한다. 종이결 텍스처와 메시·재질은 런타임에만 만들고 종료 시 해제하며 파일을 추가로 남기지 않는다. 종이결 난수는 게임 판정과 분리되어 있고 프레임마다 바뀌지 않는다.

하단 `ONE ORDER PER COLA` 문구와 `HOW TO ORDER`·담기/빼기/결제 방법·빈 장바구니 안내 문구는 제거했다. 병당 한 번의 일괄 주문 규칙은 유지한다. 아이템 설명은 별도 패널에 이름과 효과를 나누고 효과 글씨를 기존의 약 1.6배로 키웠다. 단어 단위로 줄을 바꾸며, 품목을 가리킬 때만 패널·이름·효과를 표시한다. 내려놓았을 때의 세부 인쇄 숨김은 유지한다. 이 디자인 변경은 에이전트 검증을 실행하지 않았으며 다음 Play에서 사용자가 확인한다.

## 보관함 배치 조정

내려놓은 주문서에 마우스를 올리면 클립보드 바깥 테두리에 기존과 같은 황금색·2.5픽셀 호버 아웃라인을 표시한다. 종이 글씨와 세부 버튼에는 선을 그리지 않는다. 강도 선택 여부와 관계없이 주문할 수 있을 때만 표시하며, 들기/내려놓기 중·보스 턴·연출·주문 불가 상태에서는 숨긴다. 주문서가 런타임에 생성된 뒤 기존 조작 안내에 연결한다. 이 변경도 에이전트 검증은 실행하지 않았다.

내려놓은 주문서는 작은 품목명·가격·수량·설명·얇은 구분선과 가격 버튼을 숨기고 큰 `ORDER` 표지만 표시한다. 테이블을 비스듬히 바라볼 때 작은 글씨가 자글거리는 현상을 줄이기 위한 거리별 표시 방식이며, 집으면 기존 6종 메뉴와 모든 주문 조작을 다시 표시한다. 종이 모델과 집기 콜라이더는 유지한다. 이 변경도 에이전트 검증은 실행하지 않았다.

양쪽 보관함은 배율 84%를 유지하며 원본 메시 외곽을 폭 0.60→0.55m, 깊이 0.42→0.39m로 정리했다. 두 트레이 모두 Y축 8도로 맞추고, 플레이어 중심은 `(0.62, 0.833, 0.08)`, 보스 중심은 `(0.80, 0.927, 0.62)`로 옮겨 앞뒤 간격을 확보하는 방향으로 조정했다. 보스는 테이블에 닿는 작은 받침으로 높이를 확보한다.

양쪽에 같은 3열×2줄 격자·낮은 벽·곧은 칸막이를 사용한다. 뒷줄 단차는 0.060→0.078m로 높였고, 종이 안감과 인쇄 띠도 칸 중심에 맞춰 정렬했다. 앞으로 튀어나온 손잡이와 보스의 높은 벽·큰 금속 손잡이는 제거하고 작은 옆면 손잡이 형태로 바꿨다. 색·피자 문양으로 소유자를 구분한다. 실제 아이템은 각 칸의 바닥에 놓고 형상에 맞는 클릭 범위를 둔다. 이 배치·모델 변경은 사용자의 지시에 따라 에이전트 검증을 실행하지 않았으며, 다음 Play에서 사용자가 확인한다. 기존 검증 보고서는 이 변경 전 결과다.

## 보스의 자동 주문·사용

보스도 같은 11종과 가격을 사용한다. **한 병당 한 번의 주문에 최대 3개 구매**하며 잔액과 빈 칸 안에서 유효한 품목을 함께 고른다. 자기 턴마다 **최대 2개 사용**하며 기존 보유품을 먼저 고려한다. 체력이 부족하면 피자를, 위험한 압력에서는 안전 마개·얼음컵·턴 넘기기 품목을 우선 평가한다. 나머지 상황에서는 방해·추가 보상 품목 중 적절한 것을 고른다. 공개된 압력·확률·체력과 보유 토큰으로 판단하고, 비슷한 선택에는 작은 무작위 편차를 준다. 실제 폭발 난수는 읽거나 소모하지 않는다.

체력이 부족하고 피자 가격 8토큰에 못 미치면 예상 위험 35% 미만에서는 구매를 보류해 회복 비용을 모은다. 이미 가진 사용 가능한 아이템은 계속 고려하며, 위험이 높으면 방어·턴 넘기기에 토큰을 쓸 수 있다.

주문 후 아이템 모델을 약 0.8초 보여 주고 사용 후 약 0.65초 기다린다. 양쪽 대기 효과를 표시하며 별도 보스 사용 알림 패널은 제거했다. 보스의 아이템에 마우스를 올려 정보를 볼 수 있고 플레이어가 대신 사용할 수는 없다.

아래 효과의 ‘자신’과 ‘상대’는 사용 주체에 따른다. 보스의 시럽·매운맛 주문서는 플레이어의 다음 흔들기에, 안전 마개·스탬프·팁은 보스 자신의 다음 흔들기에 적용된다. 보스가 번호표를 쓰면 다음 플레이어 턴을 한 번 건너뛰고 보스가 한 번 더 행동한다. 플레이어가 보스 턴을 건너뛰면 그 턴의 자동 주문도 실행하지 않는다.

| 11 | 팁 봉투 | 1 | 자신의 다음 흔들기가 **최종 확률 50% 이상이며 안전할 때** 토큰 +3. 조건 미달·폭발이어도 그 흔들기에서 효과 소모. |

압력 변경만으로 폭발 판정을 하지 않는다. 예를 들어 캔디로 한계를 넘겨도 다음 상대의 실제 흔들기에서 폭발한다. 개인의 다음 흔들기 효과는 계산서·캔디·상대 행동으로 소모되지 않는다. 번호표로 건너뛴 인물의 시럽·매운맛 주문서도 그 인물이 실제로 흔들 때까지 남는다.

## 구현과 검증

`ColaItemCatalog`에 이름·가격·설명을 모았다. `ColaItemController`는 양쪽 일괄 결제·병당 주문 기회·시작 아이템·슬롯·대기 효과, `ColaItemPresentation`은 실제 아이템 모델과 모서리를 깎은 보관함 메시·칸막이·손잡이를, `ColaBossItemAI`는 보스의 선택을 담당한다. `ColaItemModelLibrary`는 11종 OBJ와 공용 팔레트를 불러와 양쪽에 같은 소품을 표시한다. 모델 번호 글씨는 제거했고 기존 슬롯 입력·소유권 연결은 유지한다. `ColaOrderSheet`는 클립보드·접힌 종이·금속 클립·입체 가격/수량 빼기/주문 확정 버튼과 집기/내려놓기를 만든다. 종이는 밝은 불투명 Unlit 재질로 방 조명과 관계없이 읽을 수 있게 한다. `ColaWorldText`와 전용 글리프 셰이더는 깊이 검사를 사용하고 동적 한글 폰트의 아틀라스 갱신도 따라간다. 화면 Canvas나 GUI 상점은 사용하지 않는다. 기존 장식 아이템과 전용 보조광은 계속 비활성화한다. 플레이 중 상하 UI와 보스 사용 알림 패널은 제거하고 아래에는 배경 없이 내 효과·보스 효과 두 줄을 남겼다.

현재 UI·모델 변경은 검증을 실행하지 않았다. 아래는 사용자가 요청했을 때 실행할 기존 검증 진입점 설명이며, 기존 결과를 새 모델의 Game 뷰 확인 근거로 사용하지 않는다.

`BottlePressureModel`이 예고와 실제 판정에 같은 압력·확률 보정을 사용한다. 선택 강도와 실제 증가량을 구분하므로 시럽이 보상을 늘리지 않는다. 확정 시 효과를 스냅샷으로 보관해 병 교체가 먼저 일어나더라도 해당 폭발의 피해·보상이 보존된다.

검증 실행: `ColaCola.Editor.ColaItemVerification.Begin`. 실제 Unity Play 모드에서 11종, 여섯 큐브의 Raycast 입력, 결제 실패, 중첩 방지, 확률계 연동, 양쪽 원본 손 이동, 턴 제어, 체력·보상·승리·재시작을 확인한다. 이어 기존 `PlayableDuelVerification` 회귀 검사를 실행한다. 최신 결과는 `output/verification/latest/cola-items/Playmode-validation.txt`에 기록한다. 테스트 전용 토큰·체력 조정은 Editor 검증 코드에만 있으며 게임 시작값에는 반영하지 않는다. 자동 상태 검사이며 Game 뷰 시각 확인은 별개다.

보스 통합 검증은 `ColaCola.Editor.ColaBossItemVerification.Begin`으로 실행하고 `output/verification/latest/boss-items/Playmode-validation.txt`에 기록한다. 양쪽 12개 큐브의 화면 범위·가림 Raycast, 보스의 11종 효과와 소유권·계좌 분리, 강도 강제와 플레이어 압력계, 양방향 턴 건너뛰기·넘기기, 자동 구매 중 재시작 및 실제 0토큰 시작의 자력 구매를 검사한다. 이어 플레이어 아이템과 기본 대전 검사를 실행한다. 이 두 회귀 검사는 보스 선택 로직과 분리한 고정 조건을 위해 해당 검증 안에서만 자동 아이템 사용을 끈다.

주문서 검증 진입점은 `ColaCola.Editor.ColaOrderSheetVerification.Begin`이다. Play에서 실제 가격·수량 빼기·주문 확정 버튼의 Raycast, 취소 시 무결제, 같은 병의 이후 턴 주문, 여러 종류·수량의 정확한 일괄 결제, 부족한 총액·빈 칸·잘못된 품목의 부분 결제 차단을 검사한다. 양쪽 새 보관함의 메시·재질·여섯 칸과 12개 큐브의 화면 범위·구조물 가림 Raycast도 확인한다. 32병의 중복 없는 6종 추첨, 재열기 중 메뉴 유지, 보스와 같은 메뉴, 독립된 폭발 난수, 토큰·공간·차례·주문 여부에 따른 숨김과 잠금 해제, 11종 전체 결제, 실제 폭발 후 새 메뉴·주문 기회 및 재고 보존을 검사한다. 이어 보스·플레이어 아이템과 기본 대전의 Play 검사를 실행한다. 최신 결과는 `output/verification/latest/order-sheet/Playmode-validation.txt`와 `unity-playmode.log`부터 기록한다. 복합 효과 검사는 Editor 전용 설정으로 시작 인벤토리를 비우고 이전 병의 재고를 준비하며, 특정 품목이 필요한 시나리오는 실제 새 병 추첨으로 메뉴를 준비한다. 자동 상태 검사는 실제 Game 뷰 시각 검수를 대신하지 않는다. 프리뷰나 연속 캡처는 만들지 않는다.
